# 사업 운영의 중심

사업의 계획·보고·결정은 이 관제에서 관리한다. 웹의 **운영 → 운영 계획·보고** 또는 **사업 단지 → 운영 계획·보고**에서 사업을 고른다. 사업 전체에 적용할 결정은 **공통 운영**(`portfolio`)에 기록한다. 연결 전 사업도 계획과 보고를 기록할 수 있다. 기록 저장과 실제 작업 실행은 구분한다.

각 사업의 실행기는 해당 프로젝트에 둔다. 관제는 실제 결과·비축·일정·예외를 받아 보여 주고 지원되는 운영 지시를 전달한다. 미리캔버스의 PNG·현재 해시 검수·플랫폼 ID·제출 이력은 기존 원본 DB를 유지한다. 관제 연결이 끊겨도 이미 켜진 원본 작업기는 계속한다.

## 코드와 AI

정상 경로는 코드가 처리한다. 로그인된 실제 브라우저에서 계정, 저장값, 파일 ID, 제출 전후 상태를 확인한다. 같은 작업 재시도는 새 업로드가 아니라 기존 실제 결과 대조부터 시작한다. 반복 조회·업로드에는 AI 토큰을 쓰지 않는다.

화면 변경 등 코드로 처리할 수 없는 예외에는 Luna를 사용한다. 이 부분은 **도입 계획**이며, 현재 자동 운영에 연결됐다는 뜻이 아니다. 다음 기준을 충족한 뒤 켠다.

- 해당 계정의 짧은 오류·현재 화면 관측·마지막 성공만 전달한다. 암호·쿠키·다른 계정의 기록은 제외한다.
- 동일 오류의 반복 AI 호출을 막고 호출 시간·출력량·재시도 횟수를 제한한다. 진단과 처리 결과를 관제에 기록한다.
- AI는 화면에서 확인한 선택지만 제안한다. 계정 전환·기존 파일 삭제·재제출·세금/송금 변경은 복구 선택지로 제공하지 않는다.
- 코드가 현재 계정과 페이지, 실제 존재하는 조작 대상을 다시 확인하고 실행한다. 제출은 기존 제출기의 저장값·실제 ID 대조를 통과해야 한다.
- 인증 추가 확인이나 해결되지 않은 예외는 근거와 다음 행동을 남긴다. 확인하지 못한 결과를 성공으로 바꾸지 않는다.

도입 합격 기준은 언어 변경, 선택 상태 유지, 화면 밖 카드, 저장 후 중단 사례의 격리 재현과 중복 업로드 없는 복구다. 실제 운영에서는 13계정 한 순회를 계정별 결과와 대조하고 호출 횟수·소요 시간·미해결 건수를 보고한다.

## 미리캔버스 운영

복구 작업도 계정 작업 종료와 창 최소화 후 30분 간격을 지킨다. 20개 묶음 제출 후 실제 대기 ID를 확인한다. 심사는 2일마다 확인하고, 화면에서 안내한 예상일을 보존하며 기한이 지난 뒤에는 매일 확인한다. 제작·검수·메타데이터 작업기는 제출 간격과 독립적으로 비축을 채운다.

확인 시도 시각과 실제 성공 시각은 별개다. 자동 확인 미완료는 프로그램이 확인을 마치지 못했다는 뜻이다. 기존 업로드·제출·승인·공개 기록을 지우거나 실패로 바꾸지 않는다. 원본의 순차 확인 대기열과 다음 계정 작업 가능 시각을 관제에서 확인한다.

## 운영 기록 쓰기

사람은 관제 화면에서 기록을 추가·수정한다. 자동화 작업을 맡은 에이전트는 이 프로젝트의 CLI를 사용할 수 있다. 접속 암호는 기존 개인 파일에서 읽고 명령 인수나 로그에 넣지 않는다.

```sh
node scripts/management-record.mjs list --business miricanvas
node scripts/management-record.mjs read --id miricanvas-code-ai-recovery
node scripts/management-record.mjs save --file /경로/운영기록.json
```

기존 기록은 `read`로 먼저 읽고 수정한다. 목록이 더 있으면 반환된 `nextCursor`를 `list --cursor 값`에 넣는다. 입력은 `id`, `businessId`, `kind`(`plan`/`report`/`decision`), `title`, `content`, `status`, 선택 `dueAt`이다. 계획 상태는 `planned`/`active`/`blocked`/`done`, 보고·결정은 `recorded`를 쓴다. `archived`는 보관이다. 같은 보고를 갱신할 때 같은 `id`를 사용한다. 제목과 본문에는 실제 확인 결과, 남은 일, 다음 행동을 구분한다. 계획을 완료로 기록해도 플랫폼 제출 기록은 바뀌지 않는다.
