# BLUEKITE 사업 관제

혼자 운영하는 여러 사업을 한 공간에서 보고 다음 지시를 내린다. 첫 사업은 실제 운영 중인 미리캔버스 기여자 13계정이다. 계정의 제작, 사용 가능한 비축, 실제 제출, 심사 결과를 구분한다. 허위 성공 수치와 가짜 운영 움직임은 만들지 않는다.

## 화면

밝은 미네랄색 바닥의 입체 산업 단지. 13개 작업동에 번호와 실제 제작물을 표시하고 문제·선택 상태만 강조한다. 제작·내부 검수·비축·제출/심사 시설을 도로와 공정 방향으로 연결한다. 재고는 계정별 실제 목표 대비 10칸으로 표현한다. 움직임은 실제 작업 중인 공정에서만 재생한다. 공간이 중심이고 최근 변화·확인할 일과 하단 도구만 상시 표시한다. 카메라와 표시 레이어는 필요할 때 펼친다. 문제는 색과 아이콘을 함께 사용하고 선택하면 원인·관측 시각·가능한 조치가 나온다.

PC는 선택한 시설의 옆 패널, 모바일·태블릿 세로는 하단 시트. 3D를 돌릴 수 없는 환경에서도 계정 목록과 모든 업무 기능은 유지한다. 줌·회전·초기 시점, 키보드 선택, 터치, 동작 줄이기를 지원한다. 차트, KPI 카드 격자, 장문의 소개 문구는 넣지 않는다.

## 실제 연결

맥미니의 PostgreSQL `miricanvas_upload`를 읽기 전용으로 조회한다. 전체 PNG를 검사하는 기존 `/api/state`는 30초에 응답하지 않아 주기 조회로 사용하지 않는다. 현재 운영 정책의 `production_stock.inventory`로 목표와 공정을 읽고, `keyword_allocation.ready_count`의 제목·후보 소유권, 재시도 시각, 기제출 제외, 대표어 중복 제외 조건을 적용해 실제 제출 가능 재고를 계산한다. API 스냅샷에는 계정, 단계별 수량, 제출 이력, 일정, 작업기 상태만 허용 목록으로 복사하고 DB 접속 정보·경로·인증 정보는 보내지 않는다.

관제 자체 일정·지시는 별도 저장하며 결과를 기록한다. 원본 자동화의 설정과 연결하는 명령은 지원되는 필드만 바꾸고 기존 운영의 중복 제출 방지를 유지한다. 실데이터와 연결이 끊기면 마지막 관측 시각과 연결 끊김을 명확히 표시한다. 다른 사업은 미연결로 표시하며 사업 등록과 상태 관리가 가능하다.

## 검증

390×844, 768×1024, 1440×900, 900×1440, 가로 모바일, 키보드·200% 확대를 headless로 확인한다. 생성기 원본은 읽기 전용으로 대조하며 지시의 변경 시험은 임시 원본에서 한다. 일정 저장·재진입·취소, 잘못된 입력, 세션·권한, 연결 끊김, WebGL 실패, 3D 선택과 프레임을 확인한다.
