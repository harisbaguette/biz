## 실제 Cloudflare 배포 추가 판정

**도메인 앱의 배포는 수용한다. 상시 관제 운영의 최종 수용은 보류한다.** [biz.bluekite.co.kr](https://biz.bluekite.co.kr)의 Worker와 별도 APAC D1에서 13계정·2,761개 그림·109개 미리보기를 수신했고, 화면·인증·일정 영속 저장이 실제 HTTPS 주소에서 동작했다. 이 수신은 수동 연결 실행의 결과다.

후속 범위는 변경·증거 8개 중 8개다. `connector/bridge.py`, `tests/bridge_test.py`, `wrangler.jsonc`, `public/_headers`, `worker/index.mjs`, `tests/production.test.mjs`, 실제 도메인의 `smoke.mjs`와 `smoke.json`을 검토했다. 앞의 35개 파일 심사와 장면 전체 평가는 반복하지 않았다.

| 확인 | 증거·판정 |
|---|---|
| Python 연결 차단 복구 | 첫 원격 연결의 1010 차단 후 제품 이름을 밝히는 `BluekiteBizBridge/1.0`과 JSON `Accept`를 추가했다. 기존 Bearer 인증·JSON 본문·25초 timeout은 유지한다. 로컬 HTTP 회귀를 포함한 Python 9/9를 심사자가 다시 실행해 통과. 실제 원격 수신도 확인 |
| 배포 플랫폼의 외부 스크립트 주입 | 처음에는 Cloudflare 측 분석 스크립트가 앱의 `script-src 'self'`에 막혀 콘솔 오류가 났다. HTML의 `no-transform` 응답을 정적 헤더와 Worker 경로에 적용했다. 독립 HTTPS 조회에서 헤더 적용·beacon 주입 없음·CSP 유지 확인. 이후 양 브라우저 콘솔 오류 0 |
| HTTPS·인증 경계 | 독립 읽기 요청에서 루트 200, health 200, 비인증 session의 `authenticated:false/local:false`, world 401. 루트의 CSP·HSTS 확인. 생산 smoke에서도 개인 파일·소스 경로 404, 보안 쿠키, 잘못된 Origin 403 확인 |
| 실제 화면·업무 | Chromium/WebKit 각각 PC 1440×900·모바일 390×844·태블릿 768×1024, 6개 중 6개 장면 준비·13계정·재고·일정·가로 넘침 없음. 메모 일정 저장→새로고침 후 유지→취소, 두 엔진 로그아웃 후 world 401. JS 오류 0, 시험용 원본 지시 0 |
