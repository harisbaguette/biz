## 실제 운영 흐름을 눌러 본 판단

첫 장면에서 실제 문제 계정의 잠금과 제출·심사 시설의 `1곳 확인`, 비축 `12/3,900`을 볼 수 있었다. 제작·검수 시설은 실제 작업 중이었고, 선택하면 각각 `561개 제작 중`, `2,217개 검수 대기`와 작업기 상태로 이어졌다. 처리율·용량 자료 없이 2,217이라는 수만으로 검수가 병목이라고 단정하지 않았다.

문제 계정 선택에서 실행 장소와 로그인 선행 조치를 확인하고, 재확인을 접수했다. 대기 중에는 해당 계정에 시계 표식과 대기 카드, 비활성 지시 버튼이 남는다. fixture를 `applied`로 바꿔도 실제 확인 전에는 `지시 이후 계정 확인 대기`를 보였고, 새 `checkedAt`이 들어온 뒤에만 `지시 이후 계정 확인됨`으로 바뀌었다. 수신을 실패시키면 추가 지시는 비활성화됐다.

따라서 이전의 ‘건물을 눌러 숫자 패널만 여는 장식 단지’에서 실제 대상→선행 조치→접수 대기→반영→새 관측의 흐름으로 진전됐다. 숫자를 숨겨 놀이처럼 보이게 만든 것이 아니라, 실제 사업 상태를 선택할 수 있는 공간으로 옮긴 점은 승인한다.
