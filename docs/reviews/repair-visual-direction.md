# 수정 시각 방향 · 실제 업무가 움직이는 작은 산업 단지

**첫 화면에서 ‘어느 계정이 막혔고, 재고가 얼마나 차 있으며, 다음에 무엇을 할지’ 읽히게 한다.** 크림·청록·Kenney GLB·Pretendard는 유지한다. 떠 있는 번호판과 중복 수치를 덜고, 기능 시설·적재장·상태 형태에 정보를 옮긴다. 기존 9개 지적을 해결하기 위한 구현 지시이며 최종 합격 판정은 별도다.

### 공간: 4×4 모듈 안에 계정 13곳과 실제 공정 3곳

모듈 간격 7.2, 지면 구획 5.8×5.8, 외곽 대지는 약 34×34 world unit로 시작한다. 현재 가로로 긴 대지를 정방형에 가깝게 줄인다. 중앙 세 공정은 계정동보다 1.15배 이내로만 크게 한다.

| z / x | −10.8 | −3.6 | +3.6 | +10.8 |
|---|---|---|---|---|
| −10.8 | 계정 01 | 계정 02 | 계정 03 | 계정 04 |
| −3.6 | 계정 05 | **제작** | **검수** | 계정 06 |
| +3.6 | 계정 07 | 계정 08 | **출하** | 계정 09 |
| +10.8 | 계정 10 | 계정 11 | 계정 12 | 계정 13 |

도로는 모듈 사이 1.4~1.6 폭의 연결된 서비스 통로로 묶는다. 외곽 순환로와 중앙 제작→검수→출하 연결만 남긴다. 각 계정 앞 1.8×0.9 적재장은 차도 밖에 두고, 상태 표식·번호는 그 구획의 전면에 고정한다. 새 에셋 없이 `building-e`(제작), `building-b`(검수), `building-h`+`shipping-container`(출하)를 재사용하되 기능 표식으로 구분한다. 계정 모델의 모양은 능력·매출·우선순위를 뜻하지 않는다.

| 공간 | 실데이터 → 보이는 것 | 선택 후 |
|---|---|---|
| 제작 | `lanes.generation`, `productionEnabled` → 실행/정지/대기/오류의 형태+짧은 상태. 실제 실행 때만 작업등 작동 | 생성 상태와 원인, 켜기·정지 |
| 검수 | `lanes.review`, `lanes.metadata` → 검수와 메타데이터 작업 상태를 분리. 외부 심사와 혼동하지 않게 `검수` 이름 유지 | 두 작업기의 상태·관측 시각·복구 |
| 출하 | `automation.enabled`, `runningAccount`, 계정별 `prepared`·`submitted` → 출하 대기 적재장과 심사 대기 구획을 구분. 트럭은 실제 running 계정에만 이동 | 제출 대기·심사 일정과 해당 계정 |
| 계정 13곳 | 대표 콘텐츠 썸네일+번호로 식별. 적재장 10칸을 `ready/target` 비율로 채움: 0/300→0칸,120/300→4칸,300/300→10칸. 초과는 `+`로 표시하고 상세에 정확한 수량 | 이름·원인·정확한 재고·제외분·일정·재확인 |

**색만으로 상태를 전하지 않는다.** 정상은 작은 점, 작업 중은 삼각 재생 표식, 로그인은 열쇠, 막힘은 경고 삼각형, 오래된 관측은 끊긴 연결 표식으로 고정한다. 문제·선택 대상만 짧은 상태 이름을 추가하고 나머지 13개 이름을 상시 펼치지 않는다. 최신성 미확인 때는 공간의 마지막 값과 미확인 표식을 함께 남긴다. 정지·동작 줄이기에서도 형태가 남아야 한다.

### 화면: 3D를 위한 한 겹의 도구

| 기기 | 상시 요소 | 선택·추가 조작 |
|---|---|---|

상시 숫자는 문제 건수만 남기는 안을 우선한다. 재고·심사 합계는 해당 시설 선택 때 이름과 함께 한 번만 보여 준다. 진입은 기존 5개 메뉴로 유지해 메뉴를 늘리지 않는다. 정상 대상의 번호 표식은 투명한 44px 선택 영역 안에 작게 두며, 인접 선택 영역이 겹치지 않도록 투영 간격을 확인한다. 축척이 작아지면 13개의 불투명 판을 키우는 대신 문제 표식을 우선하고 대표 콘텐츠는 선택 시 명확히 보여 준다.

### 지형·빛·카메라

- **색의 역할:** UI 크림 `#fbfcf7`, 글자 `#203b34`, 보조 글자 `#52665b`. 지면은 탈색 녹회색 `#cbd4c4`, 도로는 더 짙은 `#7a8a7d`, 구획은 밝은 `#e5e6d6`로 시작한다. 청록 `#2f746d`는 물과 작업 중인 기능에 제한한다. 경고 바탕은 `#8c531f`+흰 글자, 오류는 `#a33e31`. 이는 후보 토큰이며 최종 렌더의 대비4.5:1·표식3:1로 확정한다.
- **운하:** 대지 북쪽 외곽에 폭2.4~3.0만 남긴다. 대지보다 수면을0.35 낮추고 양측 둑0.3, 둑 위 보행 여백0.8로 지형에 접속한다. 대지 뒤에서 사각판이 공중에 끝나지 않게 바깥 지면까지 수로를 연장한다. 수면은 배경보다 조금 짙게, 작은 정적 반사와 거친 표면만 사용한다. 업무와 무관한 풍차·태양광·물탑의 반복 배치는 제거한다.
- **빛:** 현재 방향광 하나+부드러운 환경광 유지. 지붕/차도/지면이 같은 명도로 뭉치면 환경광부터 낮추고, 그림자로 대비를 과장하지 않는다. 건물과 상자의 접촉 그림자, 대지 두께, 둑 접합을 가까이서 확인한다. 실제 미연결 설비를 발광시키거나 움직이지 않는다.
- **카메라:** PC는 정사영·고도52° 안팎/방위35°, 폰은 고도60~63°/방위15~25°로 시작한다. 픽셀 너비 구간별 고정 zoom을 쓰지 않고 단지·건물·표식 경계를 HUD 안전 사각형에 맞춘다. 초기·회전·전체 보기·resize마다 16개 시설의 선택 영역이 모두 들어와야 한다. 선택 시 패널을 제외한 안전 영역의 중심에 선택 시설을 둔다. 숫자판 충돌을 막는 최종 조건은 각도보다 우선한다.

**재심사 장면:** 6개 크기 전체/문제 계정/상세, 재고0·120·300, 실행·정지·로그인·막힘·오래된 관측을 같은 시점으로 캡처한다. 메뉴 잘림0·대상 누락0·표식 충돌0, 실제 클릭영역44px, 대비, 내용 보존을 확인한다. 여기에 통과하기 전 화려한 효과나 추가 에셋으로 품질을 주장하지 않는다.
