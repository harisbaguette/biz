# 13계정이 지금 일하고 있는가

## 반려 판정

제공된 두 화면은 재고 숫자를 가장 크게 보여 주고, 계정의 심사·예약은 선택한 뒤에도 찾게 만든다. 같은 선반과 멀리 떨어진 심사대를 도로로 연결해 계정의 한 사이클을 눈으로 추적할 수 없다. 도로·기계·그림자에 화면을 쓰면서 경영 판단을 숨긴 것이 실패 원인이다. 이전 기능 시험과 점수는 이 목적의 합격 근거로 사용하지 않는다.

## 5초 안에 알아야 하는 것

**어느 계정이 심사 중인가, 심사대가 빈 계정은 언제 다시 제출되는가, 내가 지금 풀어야 할 막힘은 무엇인가.** 심사 건수와 다음 제출은 동시에 존재하므로 한 상태명으로 합치지 않는다. 재고는 다음 제출을 뒷받침하는 보조 정보다.

## 첫 화면

하나의 지붕 없는 콘텐츠 제작소다. 위쪽 공유 제작기에서 나온 실제 그림 꾸러미가 짧은 중앙 운반 통로로 내려온다. 그 양옆에 **번호가 고정된 13개 계정 작업 구역**을 둔다. 각 구역은 앞쪽의 작은 출고 파레트, 중심의 넓은 심사대, 뒤쪽의 승인·공개 완료랙이 이어진다. 심사대에는 상자 대신 실제 그림을 붙인 제출 묶음을 놓고, 비었으면 넓은 빈 작업판을 드러낸다. 완료랙은 초록 승인 도장이 찍힌 작품 묶음으로 구별한다. 아스팔트 둘레도로, 반복 가로등, 용도 없는 로봇, 긴 운송 여행은 없앤다.

360/390px 세로는 **3열×5행**을 시작 배치로 삼는다. 각 구역에 계정 번호, `심사 20` 또는 `심사 비었음`, `결과 11/2 예상` 또는 구체적인 막힘 원인, `확인 내일 09:30` 같은 실제 다음 시각을 선택 없이 읽을 수 있게 둔다. 수동 제출 계획이 기록된 계정에만 짧은 계획 줄을 추가한다. 계획 때문에 막힌 원인이나 실행·정지 상태를 덮지 않는다. 날짜에 시각이 없으면 시각을 만들지 않는다. 13번째 옆의 빈 두 자리로 수익 장부와 제출 설정을 모은다. PC는 같은 구역을 넓게 펼치되 계정의 심사·출고·완료 관계를 분리하지 않는다. 바닥과 공유 제작기를 포함한 연속 공간이 보여야 하며, 13개의 HTML 카드에 3D 장식을 얹는 구성은 반려한다.

기본 전체 보기에서는 13계정을 모두 보여 준다. 계정을 선택하면 같은 공간 안에서 해당 작업대를 확대하고 아래 행동판을 연다. 이때 남은 좁은 공간에 13계정을 억지로 축소하지 않는다. 닫기와 전체 보기는 13계정 전경으로 돌아온다.

## 상태를 물체로 읽는 규칙

| 현재 상황 | 작업 구역의 모습 | 항상 보이는 짧은 정보 |
|---|---|---|
| 심사 중 | 심사대에 그림 묶음, 기다리는 시계. 실제 변동 때만 묶음 이동 | `심사 20` · `결과 10/25 예상` · `확인 내일 09:30` |
| 심사 비었음·다음 확인 있음 | 빈 심사판, 작은 출고 묶음과 다음 확인 시계 | `심사 비었음` · `자동 제출 대기` · `확인 내일 09:30` |
| 심사 비었음·시각 미정 | 빈 심사판, 시곗바늘을 숨긴 시계 | `심사 비었음` · `자동 제출 대기` 또는 `제작물 대기` · `다음 시각 미정` |
| 제출 관측 | 해당 구역의 꾸러미를 짧게 접수대로 옮기는 운반차 | `제출 중`은 제출 단계가 확인될 때만. 실행 잠금만 있으면 `실행 확인 중` |
| 막힘 | 잠금이 걸린 접수문 또는 공구·정지 표식. 출고하지 않음 | `로그인 계정 다름`, `결과 확인 실패` 등 실제 원인 · 다음 재시도는 그대로 표시 |
| 관측 끊김 | 마지막 물체를 유지하고 계기판의 끊긴 연결 표식, 이동 정지 | `상태 미확인` · 마지막 확인 시각 |

재고 0은 빈 파레트, 소량은 낮은 묶음, 충분하면 높은 묶음으로 보인다. 재고 수량은 작은 보조 명판에 둔다. 승인·공개로 바뀐 작품만 뒤의 완료랙으로 옮긴다. 심사 중이면서 수동 제출 계획이 기록된 경우에도 **두 정보 모두 남긴다**. 현재 원본에 없는 제출 실행 예약은 표시하지 않는다. 날짜가 지났다는 이유로 출발·승인·완료를 연기하지 않는다.

## 일정과 조작

계정별 다음 제출은 실행기가 받아들인 예약, 수동 제출 계획, 제출 조건, 미확인을 구별한다. 원본 대조 결과 `calendar.next_upload_on`은 수동 계획이며 현재 13계정 모두 값이 없다. 실제 제출 실행 예약도 없다. 따라서 지금 화면에는 제출 조건과 다음 확인·재시도 시각을 함께 보여 준다. `automation.nextAt`은 전체 순회, `nextCheckAt`은 재확인이므로 계정 제출일로 대신 쓰지 않는다. 심사 종료일도 확정 자료가 없으므로 예상으로만 표시한다. 재확인 예약은 그 시각에 요청을 대기열에 등록하며, 실제 방문·제출 완료를 보장하지 않는다. 자세한 계약은 [데이터 의미](owner-cycle-data.md)를 따른다.

심사대를 누르면 해당 계정의 **심사 내역**, 출발 시계는 **다음 일정**, 파레트는 **제출할 그림**, 완료랙은 **승인·공개**, 장부는 **월 수익**을 연다. 명판은 줄에 관계없이 한 번 누르면 계정을 선택한다. 열린 행동판에서 막힘 원인과 **계정 재확인**에 바로 접근한다. 하단은 **전체 보기 · 다음 일정 · 제출·심사 이력 · 자동화 설정**으로 행동을 직접 이름 붙인다. 확대 전에도 13계정 판단이 끝나야 하며 터치 영역은 44px 이상이다.

## 화면 참고

[Good Company 공식 화면](https://www.chasing-carrots.com/good-company/)을 직접 비교했다. 같은 바닥 위에서 적재·작업·운반 위치가 이어지고 목재·금속·종이와 공정별 색이 구분되는 구성을 참고한다. 원작 화면은 비공개 비교 자료에만 두며 제품 에셋으로 배포하지 않는다. 장식용 도로와 반복 건물을 늘리는 대신, 제작기의 출력구·짧은 운반대·계정별 심사함과 완료 보관을 읽히게 만든다.

## 구현 반려 조건

360px 기본 전경에서 13계정 중 하나라도 심사 여부·다음 확인 시각 또는 시각 미정 표시가 가려짐, 날짜를 읽으려면 선택해야 함, 재고가 심사보다 강조됨, 빈 심사대와 일하는 심사대가 같은 실루엣임, 색을 지우면 정상·막힘을 구분할 수 없음, 공유 공장과 계정 구역의 관계가 불명확함, 확인되지 않은 예약·진행을 연출함 중 하나라도 있으면 다시 만든다. 실제 13계정 자료와 빈 심사/수동 계획/다음 확인/시각 미정/막힘/관측 끊김 사례를 섞어 렌더하고 **“지금 비었고 언제 다시 확인할 계정인지, 무엇 때문에 막혔는지”를 선택 없이 지목할 수 있는지**로 판정한다.
