# 13개 계정을 한눈에 운영하는 콘텐츠 작업실

2026-10-22 재기획 기록. 2026-10-23 사용자가 공장·13창고·제출 트럭·심사·보관·월 수익을 구체 지시하고 구현을 요청했다. 현재 구현 기준은 [산업 게임 계약](industrial-game-contract.md)이다. 아래 작업대 제안과 향후 수익 항목은 이전 기획 이력이다.

## 목적

경영자가 들어와서 **13개 계정 전체가 어떻게 돌아가는지 보고, 자신이 개입할 곳과 다음 지시를 결정한다.** 기본 화면에서 계정을 찾기 위한 이동·확대·탭 전환은 필요 없어야 한다. 재미는 사업의 실제 진척과 개입 결과를 보고 느끼는 데서 만든다.

운영 가정: 정상 업무는 자동으로 진행하며, 사용자는 매번 모든 계정을 점검하는 작업자가 아니라 예외와 자원 배분을 관리하는 경영자다. 미리캔버스는 한 사업이고, 그 안의 13계정은 운영 단위다. 계정 네 묶음을 별도 지역이나 사업으로 꾸밀 근거는 없다.

## 이전 기획에서 틀린 결정

- 모바일 건물을 크게 만드는 데 집중해 13계정을 4지구로 나눴다. `mobile-game-direction.md`의 ‘13개 계정 표찰을 상시 노출하지 않는다’는 기준을 철회한다. 사용자가 전체 상태를 머릿속에서 합쳐야 했다.
- 색이 다른 건물·도로·나무를 계정과 연결했지만, 형태가 재고·제출·심사·문제의 의미를 설명하지 못했다. 에셋 통일성과 렌더 품질을 사업 이해와 혼동했다.
- ‘계정을 두 번 눌러 찾아갈 수 있다’를 합격 기준으로 썼다. ‘처음부터 13개의 차이를 동시에 알 수 있다’가 필요했다.
- 3D에서 건물을 누른 뒤 재확인하는 기능에 치중했다. 경영자가 무엇을 조정할 수 있고 그 결과를 어떻게 볼지 충분히 설계하지 않았다.
- 기존 자동 시험의 조작·오류·배포 결과는 해당 기술 범위의 근거다. 사용자 목적 충족과 게임의 재미를 승인한 근거로 재사용하지 않는다.

## 경영자가 첫 화면에서 답을 얻을 질문

| 질문 | 전경에 반드시 보일 것 | 이어지는 결정 |
|---|---|---|
| 13개 모두 돌아가고 있나? | 01–13 고정 위치, 계정별 실행·정상 대기·개입 필요·미확인 구분 | 그냥 두어도 되는지, 손대야 하는지 |
| 내가 지금 해결할 곳은? | 해당 계정의 구체적 짧은 원인. 예: 로그인, 결과 대조 | 원인 확인, 가능한 복구, 재확인 |
| 제작물이 있는데 왜 제출되지 않나? | 제출 가능 재고와 제출/심사 단계의 막힘을 함께 표시 | 정상 심사 대기인지, 제출 경로 문제인지 판단 |
| 다음 차례까지 준비가 되나? | 계정별 재고와 관측된 다음 순서·예정 | 재고 보충 또는 일정 확인 |
| 지난번 지시는 효과가 있었나? | 지시 접수·반영·실제 후속 확인을 구분한 변화 | 기다릴지, 다시 확인할지 |

‘정상’은 초록색 건물이 있다는 뜻이 아니다. 정상 대기, 의도적 정지, 실행 감지, 관측 불명을 구별한다. 연결기가 살아 있다는 사실만으로 모든 계정이 정상이라고 표현하지 않는다.

## 표현할 세계: 하나의 콘텐츠 제작·출판 작업실

**그림을 만들어 각 계정의 재고에 쌓고, 제출·심사를 거쳐 공개하는 일**을 표현한다. 건물 색에 임의의 의미를 부여하지 않고 실제 업무에 쓰는 작업대·그림·보관대·접수함을 쓴다.

- 공유 제작 장치: 제작·검수·제목/키워드 작업의 현재 상태. 13개의 독립 작업기가 동시에 돈다는 인상을 주지 않는다.
- 계정 작업대 13개: 각 계정의 실제 작업물·재고·제출/심사 상태. 번호와 위치는 고정한다.
- 작업물: 실제 그림 썸네일이 든 판 또는 인쇄물. 재고는 그 작업물이 보관대에 쌓인 모습으로 표현한다.
- 제출·심사: 계정의 접수함과 대기 보관대. 심사 대기는 고장이나 실패와 다르게 보인다.
- 공유 작업에서 계정으로 이어지는 통로: 데이터의 관계를 설명한다. 실제 이동 이벤트를 관측한 때만 작업물 이동을 재생한다. 계정별 경로 13개가 얽히는 선 장식은 만들지 않는다.

현재 KayKit 주택·상가·도로·자동차는 이 의미를 설명하는 주재료로 재사용하지 않는다. 새 팩 이름이나 가격을 먼저 고르지 않는다. 아래 자산 계약을 만족하는 형태를 선정·가공하거나 제작한다.

| 물체 | 사용자가 알아야 할 뜻 | 모양과 변화 |
|---|---|---|
| 번호가 있는 낮은 작업대 | 이 계정의 운영 자리 | 01–13 바닥 번호, 동일한 기본 구조. 장식의 크기로 계정 우열을 만들지 않음 |
| 그림 보관대 | 실제 제출 가능한 재고 | 실제 썸네일, 정확한 수량. 적재 높이는 목표 대비 범위를 나타내며 그림 한 장을 실제 파일 한 개로 오해시키지 않음 |
| 제출 접수함 | 제출 단계 | 제출 가능·순서 대기·문제로 막힘을 구분. 한 번 누르는 것이 즉시 제출이라는 인상을 금지 |
| 시계 표시가 있는 대기함 | 플랫폼 심사 중 | 실제 대기 수량·관측된 상태. 예정일만으로 승인 처리하지 않음 |
| 정지 표식과 짧은 원인 | 사람의 개입 필요 | 오류가 난 작업대·장치에만 노출. 정상 심사 대기에 같은 경고를 붙이지 않음 |
| 공유 제작 장치 | 실제 제작·검수·메타데이터 공정 | 관측된 작업에만 움직임. 제작 정체가 어느 계정의 재고에 영향을 주는지 선택 시 연결 |

에셋 채택 기준은 **이 물체가 어떤 경영 판단에 쓰이는지, 모바일에서 무엇을 알아볼 수 있는지, 어떤 실제 데이터로 변하는지**다. 의미가 없는 도로·공원·차량·섬 장식은 제외한다. 공식 디자인시스템의 버튼·아이콘·타이포는 유지하며 업무 의미를 3D에 별도로 설계한다.

## 모바일 첫 화면의 공간 계약

360×640 세로부터 13개 번호와 주요 상태를 동시에 식별한다. 기본 시점은 천장과 높은 벽이 없는 작업실의 높은 사선 직교 시점이다. 앞 물체가 뒤 작업대를 가리지 않는다. 계정을 보기 위해 카메라를 조작하지 않는다.

공간 배치의 첫 검증안은 **좌우 두 줄, 최대 7자리**다. 각 줄의 작업대를 나란히 비교할 수 있고 한 자리의 전체 선택 면적을 44px 이상 확보한다. 이는 구조 검증안이며 최종 아트 배치가 확정됐다는 뜻은 아니다.

```text
         미리캔버스 · 전체 13계정
       [공유 제작·검수 장치의 상태]

        01               08
        02               09
        03               10
        04               11
        05               12
        06               13
        07         [실제 다음 작업]

        필요한 개입 / 선택한 계정의 행동
```

위 번호는 정보 카드의 제목이 아니라 같은 작업실 바닥에 고정된 실제 선택 장소다. 표의 모양에 테두리만 입힌 것을 최종 3D 화면으로 만들지 않는다.

- 각 자리의 기본 정보는 **번호·주요 상태·제출 가능 수량**이다. 원인은 문제가 있을 때 짧게 붙인다. 재고와 심사 대기는 물체도 구분한다.
- 공유 공정 이름과 재고/제출/심사의 의미는 짧게 명시한다. 설명을 줄인다는 이유로 사용자가 뜻을 추리하게 하지 않는다.
- 선택하면 해당 작업대와 관련 공정만 강조한다. 기본 카메라가 자동으로 확대되어 다른 계정을 숨기지 않는다. 하단 행동 영역이 생기면 전체 작업실을 그 위의 가용 영역에 맞춘다.
- 상세한 그림·일정·오류 기록은 선택 후 연다. 상세를 닫으면 같은 13계정 전경과 선택으로 복귀한다. 큰 상세 화면과 13개의 모든 세부 수치를 동시에 읽힌다고 약속하지 않는다.
- 큰 글자 설정에서도 13개의 존재와 상태를 보존한다. 개별 보조 수치는 선택 상세로 옮길 수 있지만 글자를 임의로 줄이지 않는다. 구체 배치는 회색 모형에서 먼저 검증한다.
- 태블릿·PC는 같은 13개 구조에서 작업물과 연결 관계를 더 넓게 보여준다. PC를 먼저 만든 뒤 모바일에서 계정을 숨기는 방식은 쓰지 않는다.

## 경영게임이 되기 위해 필요한 조작

관측 → 우선순위 결정 → 실제 지시 → 다음 관측에서 결과 확인이 한 흐름이어야 한다. 현재 관제가 지원하는 지시와 새로 필요한 경영 조작을 구분한다.

| 결정·행동 | 현재 지원 | 기획에서의 처리 |
|---|---|---|
| 문제 계정 재확인, 재확인 일정 | 지원 | 계정 선택 후 원인을 보고 실행. 제출 지시로 이름을 바꾸지 않음 |
| 제작·제출 자동화 켜기/끄기 | 공정 단위 지원 | 공유 장치에서 실제 영향과 현재 실행 상태 확인 |
| 재고·일정·운영 계획 조회/기록 | 지원 | 선택한 작업대에서 필요한 내용만 열기 |
| 재고가 부족한 계정의 제작 우선순위 변경 | 현재 명령 API 미지원 | 핵심 추가 기능 후보. 원본 제작기의 배분 정책·지시 규격·반영 증거를 먼저 설계해야 함 |
| 계정별 목표 재고·운영 정책 조정 | 현재 관제 지시 미지원 | 같은 원칙으로 원본 정책 연동 후 제공. 장식 버튼이나 가짜 저장으로 대신하지 않음 |
| 수익·비용에 따른 계정 투자 판단 | 현재 스냅샷에 매출·비용 없음 | 향후 실제 데이터 연결 항목. 재고나 승인 수를 수익이라고 표시하지 않음 |

첫 재설계는 현재 지원되는 운영 판단과 행동을 정확히 표현한다. 경영 깊이를 더하려면 우선순위·목표·성과의 실제 제어와 데이터를 추가해야 한다. 3D 장식만으로 이 부족함을 해결했다고 하지 않는다.

## 상태별로 기획을 반박하는 사례

1. **01 로그인 필요, 08 결과 대조 필요:** 첫 전경에서 둘 다 보인다. 계정을 정렬하거나 다른 지구로 이동하지 않는다. 01을 선택해도 08의 문제가 사라지지 않는다.
2. **재고는 많지만 심사 한도가 참:** 재고 보관대와 심사 대기함이 함께 보인다. 다음 제출을 무조건 권하지 않고 정상 한도 대기를 설명한다.
3. **재고 부족, 제작은 자동 진행 중:** 부족 자체를 고장으로 표시하지 않는다. 작업 중인 공정과 대상이 관측되면 다음 진척을 볼 수 있다. 실제 우선순위 변경 기능이 없으면 변경됐다고 응답하지 않는다.
4. **연결기는 수신 중이지만 특정 계정의 실제 확인이 오래됨:** 전체 연결과 계정 확인의 신뢰도를 분리한다. 계정별 정상 확인 주기를 고려하고, 오래된 수치의 갱신 시각을 상세에서 확인한다.
5. **전부 정상 대기:** 사용자는 손댈 일이 없고 다음 실제 작업만 알면 된다. 머무르게 하려고 경고·퀘스트·가짜 이동을 만들지 않는다.
6. **지시 접수 후 아직 실제 확인이 없음:** 접수만 표시한다. 재고·제출·승인 수와 시설의 정상 여부를 임의로 바꾸지 않는다.

## 다음 제작의 통과 기준과 순서

1. 우선 이 문서의 경영 판단·계정/물체 대응을 기준으로 13계정 회색 공간 모형을 만든다. 새 에셋을 넣기 전에 정보 의미와 360×640 한 화면 배치를 검증한다.
2. 실제 사용자 과업은 ‘현재 보이는 계정 수’, ‘개입할 두 계정’, ‘재고가 있는데 제출 못 하는 이유’, ‘아무것도 하지 않아도 되는 상태’를 설명 없이 찾아 판단하는 것이다. 사용자 관찰 전에는 이해도·재미를 합격 처리하지 않는다.
3. 기본 13/13 동시 노출, 계정 선택 중 다른 계정 상태 보존, 정상 대기와 장애 구분, 관측 시각·지시 결과의 진실성, 모바일 오조작을 검증한다. ‘전체를 두 번 눌러 방문 가능’으로 대체하지 않는다.
4. 의미와 과업이 맞는 모형에만 실루엣·재질·그림·조명·피드백을 적용한다. 실물에서 판단을 더 어렵게 만드는 자산은 제거한다.
5. 첫 배포의 범위는 전경과 현재 지원 업무의 재구성이다. 생산 배분·목표 변경 등 새 제어는 별도 실행 규격이 정해진 뒤 연동한다.

이번 작업은 재기획안과 완료 기준 갱신이다. 운영 화면·업무 데이터·명령·배포는 변경하지 않았다. 사람의 이해도와 선호는 아직 검증하지 않았다.
