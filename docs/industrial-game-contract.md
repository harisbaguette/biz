# 생산부터 수익까지, 하나의 사업 단지

2026-10-23 구현 기준. 사용자의 공장·창고·운송 명세가 이전 `owner-first-plan.md`의 작업대 제안을 대체한다.

경영자는 기본 세로 화면에서 13계정 전체를 보고 빈 재고, 막힌 제출, 심사 대기, 축적된 성과를 구별한다. 계정별 지구 이동은 없앤다. 세계 시설을 누르면 그 시설에 필요한 실제 행동을 한다.

| 실제 일 | 공간과 물체 | 데이터와 행동 |
|---|---|---|
| 생산·제작 검수 | 공장, 작업 장치, 출고 컨베이어 | 관측된 lane 상태에만 가동. 일시정지·비축충족·재시도·장애 구별. 제작 자동화 지시와 검수 대상 조회 |
| 제출 가능한 재고 | 번호가 있는 낮은 개방형 창고 13개, 선반·화물 | ready/target 대비 적재. 0이면 빈 바닥. 수량은 정확한 숫자, 화물 모형은 축척 표현. 재고 목록·계정 복구 연결 |
| 제출 | 계정 창고의 적재장, 운송로, 트럭, 접수처 | 실제 다음 제출 예정일·대기 원인·문제. 실행 잠금은 정차 작업 표시이며 제출 성공으로 간주하지 않음. 제출 자동화·재확인·일정 |
| 플랫폼 심사 | 심사 센터의 계정별 보관 bay | 현재 고유 제작물 중 submitted 수량. 확인 예상일이 지나도 자동 승인하지 않으며 확인 필요로 남김 |
| 승인·공개 | 심사 뒤쪽 완성품 창고 | approved와 published를 나누어 누적. 현재 고유 제작물을 세고 재시도 이력 중복 제외 |
| 월 수익 | 회계 시설, 계정별 12개월 장부 | 실제 수익 연동이 없어 수동 확정 원장. 미기록과 확정 0원을 구별. 계정·년도·월·원화 금액·메모 저장 |

창고의 번호와 위치는 고정한다. 개별 선택은 다른 계정을 자동으로 숨기지 않는다. 창고 자체와 표찰 모두 선택할 수 있다. 상세를 닫으면 같은 공간으로 돌아온다. 기본 전경은 360px 세로부터 13개 창고가 동시에 들어오며, 태블릿과 PC도 같은 구조를 유지한다.

버튼과 장부는 지정 Pattove 공용 컴포넌트를 바탕으로 산업 게임의 패널·명판·도구처럼 마감한다. 세계가 주 화면이며 큰 KPI 카드와 지구 탭을 없앤다. 조작 대상은 최소 44px, 큰 글자·키보드·화면 읽기·WebGL 복구를 보존한다.

## 관측의 한계

- 접속 갱신 실패는 재고 0이나 정상 정지로 바꾸지 않는다. 마지막 관측을 표시하고 지시는 막는다.
- 실행 잠금은 작업 중이라는 증거일 뿐, 실제 제출 단계나 성공의 증거가 아니다. 트럭 반복 주행으로 가짜 실적을 만들지 않는다.
- 심사·보관 수량은 연결된 현재 제작물 기준이다. 플랫폼 전체 수익과 기존 미연결 작품을 추정하지 않는다.
- 심사 종료 시각은 확정 정보가 없다. 예상 확인일을 보여 주고 실제 후속 관측을 기다린다.
- 수익 자동 수집은 연결되지 않았다. 입력한 월수익만 합산하며 빠진 달을 0원으로 간주하지 않는다.

## 검증 기준

13개 동시 가시성, 실제 물체 선택, 0/낮음/가득참 적재 차이, 정지/작업/고장/관측끊김 구분, 심사 예정 경과 후 미완료 유지, 12개월 원장 저장·재조회·동시수정 충돌을 격리 환경에서 확인한다. 모바일·태블릿·PC 화면을 직접 렌더해 읽는다. 코드 시험 통과를 게임의 재미나 사용자 만족으로 대신하지 않는다.
